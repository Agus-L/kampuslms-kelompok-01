1. Matikan worker. Buat satu tugas baru. Buka tabel `jobs` — apa isinya?
Jawab: Setelah worker dimatikan dan dosen membuat tugas baru, di dalam database pada tabel `jobs` muncul satu baris antrean baru. Kolom-kolomnya berisi data antrean asinkron Laravel:
- `id`: Berisi integer unik pengenal job antrean (misal: `1`).
- `queue`: Bernilai `'default'` (nama antrean standar sistem).
- `payload`: Berisi string JSON panjang yang menyimpan informasi detail perintah yang diantrekan, termasuk nama class Listener (`App\Listeners\SendAssignmentPublishedNotification`) dan serialized object event `AssignmentPublished`.
- `attempts`: Bernilai `0` yang menandakan antrean ini belum pernah dicoba dieksekusi oleh worker.
- `reserved_at`: Bernilai `NULL` karena saat ini tidak ada worker aktif yang sedang mengunci atau memproses job tersebut.
- `available_at` & `created_at`: Berisi nilai timestamp UNIX saat tugas tersebut pertama kali dimasukkan ke tabel antrean.

Job ini tertahan (pending) di tabel `jobs` dan notifikasi tidak akan pernah terkirim ke mahasiswa sampai ada proses worker yang dijalankan di server.

2. Baca kolom `payload`. Bisakah Anda mengenali nama Listener dan ID tugasnya?
Jawab: Ya, dapat dikenali dengan sangat jelas. Di dalam struktur string JSON pada kolom `payload`:
- Nama Listener dapat langsung terbaca pada atribut `"displayName"`: `"App\\Listeners\\SendAssignmentPublishedNotification"`.
- ID tugas dapat dikenali pada bagian payload `"data" -> "command"` yang memuat representasi string serialisasi objek PHP dari event `AssignmentPublished`. Di dalamnya terdapat referensi model Eloquent `App\Models\Assignment` beserta atribut tugasnya, termasuk `"id";i:15;` (atau ID tugas terkait). Hal ini membuktikan bahwa Laravel menyimpan identitas model ke dalam antrean database agar nantinya worker dapat me-reload model tersebut dari database saat antrean dieksekusi.

3. Jalankan `php artisan queue:work`, amati keluarannya. Periksa tabel `jobs` lagi.
Jawab: Ketika perintah `php artisan queue:work` dijalankan pada terminal, worker segera mendeteksi adanya antrean pending dan mengeluarkan output proses eksekusi:
```text
[2026-10-...] Processing: App\Listeners\SendAssignmentPublishedNotification
[2026-10-...] Processed:  App\Listeners\SendAssignmentPublishedNotification
```
Setelah proses tersebut selesai dengan status `Processed`, saya memeriksa kembali tabel `jobs` di database menggunakan Tinker (`DB::table('jobs')->count();`) dan hasilnya adalah 0 (kosong). Hal ini terjadi karena mekanisme bawaan queue worker Laravel secara otomatis menghapus baris job dari tabel `jobs` sesaat setelah antrean berhasil dieksekusi (completed successfully) agar database tidak penuh oleh riwayat antrean yang sudah selesai.

4. Periksa tabel `notifications`. Berapa baris yang muncul? Cocok dengan jumlah mahasiswa?
Jawab: Setelah antrean berhasil diproses oleh worker, tabel `notifications` langsung terisi sejumlah baris baru yang cocok persis dengan jumlah mahasiswa yang terdaftar (enrolled) pada mata kuliah tugas tersebut. Jika pada mata kuliah bersangkutan terdapat 5 mahasiswa terdaftar, maka tepat muncul 5 baris notifikasi baru di tabel `notifications`. Setiap baris memiliki kolom `notifiable_type = 'App\Models\User'` dan `notifiable_id` yang sesuai dengan ID masing-masing mahasiswa penerima.

5. Baca kolom `data` pada satu notifikasi. Adakah yang tidak seharusnya tersimpan di situ?
Jawab: Pada notifikasi publikasi tugas baru (`AssignmentPublishedNotification`), kolom `data` menyimpan payload JSON berupa metadata tugas: `assignment_id`, `course_id`, `course_name`, `title`, `due_at`, `message`, dan `action_url`. Seluruh data ini aman untuk disimpan karena bersifat publik bagi peserta kelas.

Namun, hal penting yang TIDAK BOLEH disimpan di kolom `data` adalah data sensitif atau privat, seperti pada notifikasi pemberian nilai (`SubmissionGradedNotification`). Di sana tidak boleh dimasukkan nilai angka mahasiswa (`score`) maupun catatan evaluasi dosen (`feedback`). Kolom `data` di tabel `notifications` tersimpan dalam format teks biasa (tidak terenkripsi) dan dapat dibaca oleh siapa pun yang memiliki akses ke database atau akun berlevel admin. Hal ini berisiko membocorkan privasi akademik mahasiswa. Praktik yang benar adalah kolom `data` hanya menyimpan ID notifikasi dan pesan umum, sementara nilai dan feedback hanya boleh dilihat melalui halaman detail tugas yang dilindungi otorisasi Policy.
